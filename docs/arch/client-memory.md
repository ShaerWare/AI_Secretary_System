# Client memory: the client card

> Part of the project map in [CLAUDE.md](../../CLAUDE.md); update it in the same PR as the code it describes.

**Client card** (`modules/clients/`, CRM page tab «Клиенты», issue #870): what the assistant remembers about a client between dialogues. One `client_profiles` row per `(workspace_id, channel, external_id)`, where `external_id` is the chat session's `source_id` (`"wa-<instance>:<phone>"` for WhatsApp) — **not** the session id. That distinction is the point: the WhatsApp/Telegram bots keep the phone → session mapping in process memory only (`LLMRouter._session_map`), so every bot restart or deploy opens a fresh, empty session for the same person. The card survives that. Table is created by `create_all`, no migration.

**Flow.** Task `client-cards` (`TaskRegistry`, every 10 min) picks sessions of enabled instances whose last message is older than `idle_minutes` (default 30) and newer than the card's `last_message_at` marker, max 20 per tick. One LLM call per session (`container.llm_service`, off the event loop via `asyncio.to_thread`): current card + only the messages after the marker → new card in fixed sections (Кто / Компания и город / Что спрашивал / Что получил / Договорённости / Открыто). Only assistant messages since the marker → marker moves, no LLM call. LLM failure → marker stays, retried next tick. Manual fold: `POST /admin/clients/refresh {session_id}`.

**Into the dialogue.** `modules/chat/facade.py:_inject_client_card` (both `send_message` and `stream_message`, after context files) appends `client_memory_service.prompt_block(session)`: the card, the manager's notes, and the client's latest КП read **live** from `kp_quotes` by `target` (number, status, valid-until). The block is framed as data, not instructions, and says prices/stock must come from the current catalog search. A lookup failure is logged and the reply goes on without the card.

**What never goes into the card — enforced in code.** `clean_card()` drops every line with an amount of money (₸/тг/тенге/$/руб, «цена: N») or a stock statement («в наличии», «остаток»), both on the LLM's answer and on a manager's manual edit. Prices change daily and live in `OfferService`; a remembered price is exactly the invented price the client forbade. The summarization prompt also tells the model to record client «commands» as facts («клиент просил скидку»), because the card ends up in the system prompt.

**Switch.** Off by default. Per channel instance in `system_config` key `client_memory` (`{"instances": {"whatsapp:<id>": true}, "idle_minutes": 30}`), same shape as `outbound_approval`, switched live from the «Клиенты» tab — no bot restart. Only `whatsapp` is supported (`CHANNELS` in `modules/clients/service.py`): its `source_id` is a stable client address; Telegram sessions use a different source name and widget visitors have no stable id yet.

**Admin API** (`/admin/clients`, RBAC `sales` like the rest of the CRM page): `GET/PUT /settings`, `GET ""` (search `q` over name/number/card), `GET/PUT/DELETE /{id}`, `POST /refresh`. `manager_notes` is written only by people — the LLM never receives it as text to rewrite. `DELETE` is physical (a client asked to be forgotten); dialogues stay. Tests: `tests/unit/test_client_memory.py`.
